### 새로 배운 내용
#### 주제 1: Spring Web MVC
- Spring Web MVC
  - 정리 : 스프링 기반으로 Model, View, Controller로 나누어 개발하는 아키텍처
    - 개념 : 웹 요청을 Controller로 받아 처리 흐름을 제어하고, Model과 View를 연결해 응답을 생성하도록 설계된 Spring 기반 웹 MVC 프레임워크
        - 왜 사용함?
            - 그 이유는 책임을 나누어서 복잡함을 줄이고, 재사용성과 유연성을 확보하기 위해 사용한다.
                - 그렇게 생각한 이유는 관심사를 분리하여 뷰에 대한 수정사항은 뷰 부분만 고치면 되고 유저에 문제가 생겼으면 Model 부분에서만 고치면 되기 때문에 복잡함이 줄어든다.
                - 두번째로 Model에 유저를 여러 뷰의 재사용하여 사용할 수 있고 유연하게 사용할 수 있다. 뷰에서 여러 형식으로 보여줄때 형식만 바꿔서 보내주면 끝(유연성)

#### 주제 2: Dispatch Servlet
- Dispatch Servlet
    - 정리 : 요청과 응답할 때에 공통 로직을 묶어 놓은 서블릿
    - 개념 : 요청을 직접 처리하지 않고, 어떤 컨트롤러와 처리 흐름으로 보낼지 결정하는 중앙 라우터 역할을 한다고 할 수 있습니다.
    - Re정리 : 요청을 받고 요청에 맞는 적절한 흐름으로 안내해주는 가이드 역할
        - 왜 사용함?
            - 예를 들어 유저에 대한 서블릿을 정의하여 요청과 응답을 처리 했다고 가정합시다.
            - 그런데 개발을 하면서 게시글에 대한 로직을 구현하려고 하는데 이 게시글도 서블릿을 요구합니다. (서블릿은 요청과 응답에 대한 로직을 구현한 코드)
            - 그러면 모델이 하나씩 늘어날수록 각 모델에 대한 요청,응답을 처리하는 서블릿에 코드도 증가하게된다.
            - 이러한 코드 중복을 제거하고 일관성을 제공하기 위해 스프링은 서블릿을 제공하여 공통으로 관리하고 효과적으로 처리할 수 있게 여러개의 핵심 클래스로 처리한다.
                - Handler Mapping
                    - 요청에 맞는 처리흐름을 결정하는 역할, 응답을 사용자에게 보내는 역할
                - Handler Adapter
                    - 처리 흐름에 따라 비즈니스 로직에 요청하고 처리 값을 반환하는 역할
                - View Resolver
                    - 반환 값을 View 객체로 변환해준다.

#### 주제 3: 대칭키 & 비대칭키
- 대칭키
    - 정리 : 같은 키로 암호화, 복호화 하면 통신하는 방식
    - 개념 : 데이터를 암호화하고 복호화할 때 동일한 하나의 키를 사용하는 암호화 방식
    - Re정리 : 동일한 하나의 키로 암호화와 복호화 하는 암호화 방식
        - 왜 사용함?
            - 처리 속도가 빠르기 때문!
            - 단점
                - 키를 공유하는 과정에서 노출될 위험이 있다.
                - 사용자가 늘어날수록 키의 수도 늘어난다.
                - 키 교환이 어렵다.
- 비대칭키
    - 정리 : 암호화는 공개키, 복호화는 개인키를 사용하여 통신하는 방식
    - 개념 : 암호화와 복호화에 서러 다른 키를 사용하는 기술
    - Re정리 : 암호화(공개키)와 복호화(개인키)에 서로 다른 키를 사용하여 암호화 하는 방식
        - 왜 사용함?
            - 보안성이 매우 뛰어남! - 조단위를 넘는 값을 수학적 알고리즘으로 암호화,복호화를 함ㄷㄷ
            - 그러다 보니 속도가 느리다는 단점이 있다.

#### 주제 4: HTTP
- HTTPS
    - 정리 : HTTP에 보안을 더 강화하여 통신하는 프로토콜
    - 개념 : 웹 브라우저와 웹 사이트 간의 데이터를 암호화하여 안전하게 전송하는 통신 프로토콜
    - Re정리 : 웹 브라우저와 웹 사이트 간의 통신 HTTP에서 통신하는 데이터를 암호화하여 안전하게 전송하는 통신 프로토콜 말함(HTTPS)
        - 왜 사용함?
            - 초기 웹은 정보에 제공만 했기 때문에 보안이 필요가 없었다. 보라고 올린것이기 때문
            - 근데 웹이 점점 발전하면서 정보에 제공뿐만 아니라 나를 인증하거나 결제에 수단으로도 사용을 하게 되면서 민감한 정보나 개인정보를 취급하기 시작했다.
            - 그러다보니 데이터의 보안이 중요해지면서 통신을 할때에 데이터를 더 안전하게 통신하기 위해 HTTPS를 통해 데이터를 암호화 하여 통신을 하게 되었다.
