### 새로 배운 내용
#### 주제 1: Gradle의 개념과 프로젝트 구조 제어

* **오픈소스 빌드 자동화 도구**: Gradle은 Groovy 및 Kotlin DSL 기반의 선언적 빌드 언어를 제공하며, JVM 환경에서 빠르고 안정적인 빌드 아키텍처를 구축합니다. 기반이 되는 Groovy는 자바와 문법적 유사성이 높아 진입 장벽이 낮습니다.
* **settings.gradle을 통한 멀티 모듈 제어**: 빌드 프로세스의 최상단에서 단 하나만 존재하는 루트 프로젝트를 정의합니다. rootProject.name으로 전체 이름을 지정하고, include("subProject1")과 같은 방식으로 하위 모듈들을 선언하여 프로젝트의 유기적인 계층 구조를 형성합니다.
* **build.gradle 기반의 환경 구성**: 각 서브 프로젝트의 명세서 역할을 수행합니다. 핵심 기능을 확장하고 Task를 주입하는 plugins, 외부 라이브러리를 관리하는 dependencies, 주입된 플러그인의 속성을 제어하는 convention properties (예: application { mainClass = '...' })를 설정합니다.

#### 주제 2: Dependency Manager를 통한 의존성 격리 및 제어 규칙

* **의존성 라이프사이클 자동화**: 프로젝트 수행에 필요한 외부 JAR 파일, 플러그인, 라이브러리를 로컬 및 원격 저장소에서 자동으로 탐색 및 다운로드하고, 최종 생성된 산출물을 다시 외부로 배포하는 전체 과정을 제어합니다.
* **컴파일 및 런타임 시점의 세부 구성**: 가져온 라이브러리가 유효한 단계를 지정하여 빌드 효율성을 극대화합니다. implementation과 api는 컴파일과 런타임 모두에 활용되지만 전파 여부가 다르며, compileOnly는 롬복(Lombok)처럼 컴파일 시점에만 쓰이고 런타임 산출물에서는 영리하게 제외됩니다.
* **테스트 및 실행 환경 분리**: 테스트 빌드 시점에만 작동하는 testImplementation, testCompileOnly, testRuntimeOnly 구성을 통해 테스트 환경의 의존성이 실제 운영 배포용 JAR 파일에 포함되지 않도록 완벽히 격리합니다.

#### 주제 3: Tasks 기반의 빌드 최적화 및 메커니즘

* **작업의 최소 단위와 의존성 그래프**: Gradle 내부의 모든 컴파일, 테스트, 패키징 작업은 독립된 Task 형태로 존재합니다. 각 작업은 선후 관계를 가지며, Gradle이 이를 분석하여 자동으로 최적의 순서가 보장된 '작업 실행 그래프'를 구성합니다.
* **증분 빌드(Incremental Builds)를 통한 시간 단축**: 이전 빌드 결과와 비교하여 입력 소스코드나 출력 파일에 변화가 없는 Task는 과감히 실행을 건너뜁니다. 변경 사항이 없을 때는 UP-TO-DATE, 대상 소스가 부재할 때는 NO-SOURCE 레이블을 출력합니다.
* **빌드 캐싱(Build Caching)의 비용 절감**: 브랜치 전환 등으로 인해 파일 상태가 바뀌어 증분 빌드를 적용하지 못할 때 강력한 효용을 발휘합니다. 로컬 또는 원격 캐시 저장소에서 이전의 성공적인 산출물을 그대로 복원(FROM-CACHE)함으로써 무거운 컴파일 과정을 생략하고 비용을 아낍니다.

#### 주제 4: 빌드 생명주기(Build Lifecycle)의 3단계 흐름 분석

* **1단계: 초기화 (Initialization)**: 빌드의 첫 단추로, settings.gradle 스크립트를 감지하고 평가합니다. 싱글 프로젝트 혹은 멀티 모듈 구조를 명확히 분석한 뒤, 빌드 대상이 되는 타겟 프로젝트 모듈들의 인스턴스를 메모리상에 생성합니다.
* **2단계: 구성 (Configuration)**: 초기화 단계에서 생성된 모듈 인스턴스를 바탕으로 모든 build.gradle 스크립트를 실행 및 평가합니다. 이 과정에서 선언된 Task들의 속성, 플러그인, 입출력 의존 관계를 촘촘히 엮어 거대한 '작업 실행 그래프'를 구조화합니다.
* **3단계: 실행 (Execution)**: 구성 단계에서 도출된 작업 실행 그래프를 기반으로 실제 연산을 수행하는 최종 단계입니다. 사용자가 요청한 특정 Task와 그에 엮인 전행 Task들이 순서대로 실행되며, 자바 소스가 컴파일되고 테스트가 수행되어 최종 실행 산출물(JAR)이 생성됩니다.
