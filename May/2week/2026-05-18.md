### 새로 배운 내용

#### 주제 1: 웹(Web)과 HTTP 통신 기초

* **Web & Client & Server**
* **Web**: 인터넷에 연결된 컴퓨터들을 통해 정보를 공유하고 접근할 수 있는 정보 공간 (World Wide Web).
* **Client**: 요청을 하는 주체. 서버의 원격 서비스에 접속하는 응용 프로그램이나 서비스.
* **Server**: 정보나 여러 기능을 제공해주는 시스템. 컴퓨터 프로그램 또는 장치.


* **HTTP (HyperText Transfer Protocol) 및 구성 요소**
* **HTTP**: 일반적인 텍스트를 뛰어넘는 구조화된 텍스트(html, css, js, 이미지 등)를 전송하기 위해 사용되는 통신 규약.
* **HTTP Message**: 클라이언트와 서버 간에 주고받는 통신의 기본 단위 (편지 역할).
* **HTTP Method**: 웹 서버에게 어떤 작업을 수행하길 원하는지 알리는 명령 규칙 (편지의 행위).
* **HTTP Status Code**: 통신 진행 상태를 코드로 나타내어 상태를 표시 (편지의 상태).
* **HTTP URL**: 리소스의 위치와 종류를 나타내는 웹 상의 주소지.


* **데이터 전달 방식**
* **Query String**: 클라이언트에서 웹 페이지에 대한 추가 정보를 서버에 전달하기 위해 질문 형식으로 사용하는 문자열.
* **Path Variable**: 경로 부분에 포함되어 특정 자원을 식별하는 변수. 특정 주소지(길)에 접근할 수 있게 함.



#### 주제 2: RESTful API와 스프링 프레임워크 코어

* **RESTful API**
* **정의**: REST 아키텍처 스타일을 따르는 응용 프로그램 인터페이스.
* **사용 이유**: 개발자 간의 의사소통법을 정해 효과적으로 통신하고, 요청 시 구조화된 정보를 제공하여 기능을 효과적으로 수행, 전체적인 성능을 높이기 위함.


* **스프링(Spring) 프레임워크 기초**
* **정의**: 자바 엔터프라이즈 개발을 편하게 해주는 오픈소스 경량급 애플리케이션 프레임워크.
* **사용 이유**: POJO 기반의 구성으로 독립적인 환경에서 객체지향적인 개발에만 몰두할 수 있게 도와주기 때문.


* **핵심 원리: IoC, DI, AOP**
* **IoC (제어 역전)**: 개발자가 하던 객체 생성 및 관리를 프레임워크가 대신하도록 제어권을 넘긴 것.
* **DI (의존성 주입)**: 객체를 직접 생성하지 않고 외부(컨테이너)에서 주입받는 방식. 결합도를 낮추고 유지보수성과 유연성을 확보하며, 테스트 용이성을 높이기 위해 사용.
* **AOP (관점 지향 프로그래밍)**: 공통 관심사와 핵심 관심사를 분리하여, 공통 기능을 한곳에 모아 코드 중복을 줄이고 일관되게 적용하기 위함.


* **Spring Bean & Bean Container**
* **Spring Bean**: 스프링 IoC 컨테이너가 생성하고 관리하는 재사용 가능한 자바 객체. (객체 관리의 일관성, 안정성, 확장성 확보)
* **Bean Container**: 어노테이션으로 지정한 여러 객체들이 모여 생성되고 관리되는 공간. 의존성 주입을 위해 외부에서 객체를 생성하고 관리하는 목적.



#### 주제 3: 스프링 딥다이브와 POJO 프로그래밍

* **스프링의 본질과 목적**
* 특정 계층에 국한되지 않는 **범용적 애플리케이션 프레임워크**이며, 톰캣과 같은 단순한 환경에서도 동작하는 **경량급** 기술.
* 궁극적인 목적은 기술적 복잡함을 프레임워크가 처리해주어 개발자가 비즈니스 로직에만 집중하게 함으로써 **엔터프라이즈 애플리케이션 개발을 편하게 하는 것**.


* **엔터프라이즈 개발의 복잡함과 스프링의 전략**
* 과거 EJB는 특정 인터페이스나 클래스를 상속해야 하는 **침투적인 방식**으로 객체지향의 장점을 망치고 복잡도를 높임.
* 스프링은 **비침투적인 방식**을 채택. 서비스 추상화, 템플릿/콜백, AOP를 통해 기술 관련 코드를 비즈니스 로직과 분리. 이 모든 기술적 전략의 바탕에는 DI(의존성 주입)가 있음.


* **POJO (Plain Old Java Object)**
* **조건**: 특정 환경, 기술, 규약에 종속되지 않고 객체지향적인 자바 언어의 기본에 충실하게 만들어진 순수한 오브젝트.
* **장점**: 환경에 구애받지 않으므로 자동화된 테스트에 매우 유리하며, 객체지향적인 설계를 자유롭게 적용할 수 있음. 결국 스프링은 개발자가 진정한 POJO 프로그래밍을 할 수 있도록 돕는 도구임.

### 오늘의 회고

* 스프링 프레임워크가 단순히 유용한 라이브러리의 모음이 아니라, 자바의 가장 큰 장점인 '객체지향 설계'를 방해 요소 없이 온전히 사용할 수 있도록 판을 깔아주는 도구라는 점을 깊이 이해하게 되었다.
* 기술적인 복잡함은 프레임워크가 DI와 AOP로 해결해주지만, 정작 핵심인 '비즈니스 로직의 복잡함'을 해결하는 것은 오롯이 개발자의 객체지향적 설계 역량에 달려있음을 깨달았다.
* 앞으로 스프링 사용법에만 매몰되지 않고, 객체지향 설계 원칙(SOLID)과 디자인 패턴, JVM 및 리팩토링 기술 등 자바 생태계의 근본적인 지식을 꾸준히 훈련해야겠다.
