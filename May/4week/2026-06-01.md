### 새로 배운 내용
#### 주제 1: Spring Framework & Spring Boot의 핵심 개념
- **Spring의 존재 이유**: 대규모 엔터프라이즈 애플리케이션 개발의 복잡성을 낮추고 생산성을 높이기 위해 탄생했습니다.
- **Spring의 3대 핵심 특징**:
    - **AOP(관점 지향 프로그래밍)**: 로깅, 트랜잭션 등 공통 관심사와 비즈니스 로직을 분리하여 모듈화합니다.
    - **IoC/DI(제어 역전/의존성 주입)**: 개발자가 아닌 프레임워크가 객체의 생명주기를 관리하고 의존성을 주입합니다.
    - **POJO(Plain Old Java Object)**: 외부 라이브러리나 특정 프레임워크에 의존하지 않는 순수 자바 객체를 기반으로 동작합니다.
- **Spring Boot의 핵심 기능**:
    - **Auto-Configuration(자동 설정)**: 자주 사용하는 라이브러리와 빈을 자동으로 설정(`@SpringBootApplication`을 통해 웹 프로젝트 자동 인식 등)합니다.
    - **Starter Dependencies**: 특성(Web, Data, Security 등)에 필요한 라이브러리를 묶음으로 제공하여 의존성 관리를 단순화합니다.
    - **Embedded Server**: 내장 WAS(Tomcat 등)를 포함하고 있어 외부 서버 구축 없이 JAR, WAR 파일로 즉시 실행이 가능합니다.

#### 주제 2: Annotation(어노테이션)의 역할과 활용
- **개념**: 사람이 읽는 주석의 역할뿐만 아니라 컴파일러 및 런타임 엔진이 읽고 처리하는 기계용 메타데이터입니다.
- **사용 이유**:
    - 과거 XML 설정 파일과 자바 코드로 분리되어 있던 설정을 코드 영역으로 결합시켜 **설정의 응집도**를 높입니다.
    - 컴파일 시점에 체크하는 `@Override` 같은 **정적 검증**과, `@NotNull`, `@Size` 같이 런타임에 값을 검증하는 **동적 검증**을 자동화할 수 있습니다.

#### 주제 3: ORM과 JPA (Java Persistence API)
- **ORM(오브젝트 관계 매핑)**: 자바의 객체와 RDB의 테이블을 연결하여 객체지향 코드로 데이터를 조작할 수 있게 하는 기술입니다.
- **객체지향 VS RDB의 패러다임 불일치**:
    - **상속**: 자바는 상속/다형성을 지원하지만 RDB는 상속 개념이 없어 구조가 복잡해집니다.
    - **연관관계**: 자바는 단방향 참조 관계를 가지나, RDB는 외래키와 JOIN을 통해 양방향 관계를 형성합니다.
    - **데이터 탐색**: 객체는 참조를 통한 그래프 탐색을, RDB는 SQL 쿼리에 의존하여 데이터를 탐색합니다.
- **JPA의 역할**: 개발자가 직접 JDBC를 다루지 않도록 중간에서 대리인 역할을 수행하며, 객체를 전달하면 엔티티 구조를 분석해 적절한 SQL을 알아서 생성하고 JDBC 커넥터를 통해 실행합니다.

#### 주제 4: 엔티티(Entity)와 DTO(Data Transfer Object)
- **Entity**: 데이터베이스 테이블과 매핑되는 클래스로, 데이터의 구조뿐만 아니라 제약조건, 연관관계, 비즈니스 로직을 한곳에 모아 관리(응집)하고 유효성을 유지합니다. 기본 생성자는 지정을 위해 `protected`로 제한하는 것이 권장됩니다.
- **DTO**: 계층 간 데이터 전달을 위해 사용하는 값 보관용 전용 객체입니다. 보안에 민감한 정보(비밀번호 등)나 내부 엔티티 구조를 외부에 노출하지 않고 필요한 데이터만 안전하고 규격화하여 전달하기 위해 사용합니다.

#### 주제 5: @Id와 기본키(PK) 생성 전략
- **@Id**: 엔티티의 식별자를 지정하는 어노테이션으로, 주로 `@GeneratedValue`와 함께 사용됩니다.
- **기본키 생성 전략의 종류**:
    - **IDENTITY**: 식별자 생성을 DB에 전적으로 위임합니다. DB에 저장되어야만 ID 값을 알 수 있으므로, JPA의 핵심 기능인 **쓰기 지연(배치 처리)을 무시**하고 매번 즉시 DB 요청을 보냅니다.
    - **SEQUENCE**: 데이터 삽입 전에 시퀀스로부터 키 값을 미리 확보할 수 있어 쓰기 지연 및 배치 처리에 유리합니다. `allocationSize` 옵션을 통해 성능 최적화가 가능합니다.
    - **TABLE**: 키 생성 전용 테이블을 사용하여 시퀀스를 흉내 내는 방식으로, 모든 DB에 이식성이 좋으나 실무에서는 성능 상 잘 사용하지 않습니다.
    - **AUTO**: 사용하는 데이터베이스 방언에 맞춰 JPA가 자동으로 적절한 전략을 선택해 줍니다.

### 오늘의 도전 과제와 해결 방법
- 도전 과제 1: JPA 기본키 생성 전략 중 `IDENTITY` 전략 사용 시 쓰기 지연이 발생하지 않는 문제 파악
    - **해결 방법**: `IDENTITY` 전략은 DB가 기본키를 생성하기 때문에 쓰기 지연 저장소에 쿼리를 모았다가 한 번에 보낼 수 없고, `em.persist()` 호출 즉시 INSERT 쿼리가 수행됨을 이해함. 성능 최적화가 극도로 필요한 대용량 배치 작업 시에는 `SEQUENCE` 전략이나 별도의 벌크 연산 고려가 필요함을 정립함.

### 오늘의 회고
- 그동안 여러 프로젝트에서 JPA를 자주 사용해 왔기에 어느 정도 잘 알고 있다고 생각했다. 하지만 오늘 강의를 통해 핵심 개념들을 공부하면서, 정작 내가 JPA에 대해 모르는 부분이 너무나 많았다는 것을 깊이 깨달았다.
- 개념을 하나씩 명확히 짚어가니 모호했던 코드들이 내부에서 어떤 방식으로 돌아가고 있었는지 비로소 이해할 수 있었다. 앞으로 진행할 프로젝트에서는 단순히 기능 구현에만 그치지 않고, 배운 개념들을 직접 적용해 보며 JPA를 깊이 있게 탐구해 나갈 것이다.
