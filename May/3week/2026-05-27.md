### 새로 배운 내용

#### 주제 1: HTTP 자격 증명 헤더 및 인증 방식

* **HTTP 자격 증명 헤더**: 클라이언트와 서버 간 인증 과정에서 사용자의 신원 및 접근 권한을 증명하기 위해 요청 헤더에 담아 전송하는 필드입니다.
* **Basic Authentication**: 사용자 이름과 비밀번호를 `이름:비밀번호` 형태로 결합한 후, Base64로 인코딩하여 `Authorization` 헤더에 담아 보내는 가장 단순한 기본 인증 방식입니다.
* **Bearer Token**: "이 토큰을 소지한 사람에게 권한을 부여한다"는 의미로, 서버에서 발급한 보안된 텍스트 문자열(토큰)을 헤더에 담아 신원 및 권한을 검증받는 방식입니다.

#### 주제 2: JWT (JSON Web Token)

* **JWT의 정의**: 정보를 JSON 형식으로 안전하게 내포하고 있는 자체 포함형(Self-contained) 토큰으로, 서버가 별도의 세션 상태를 저장하지 않고도 토큰 자체만으로 사용자의 신원과 권한을 확인할 수 있게 합니다.
* **JWT 사용 이유**: 서버에 세션 상태를 저장하지 않으므로 서버 자원을 아끼고 데이터베이스 조회 비용을 줄여, 대규모 트래픽 환경에서 시스템의 **확장성**과 **성능**을 극대화하기 위함입니다.
* **JWT 인증 흐름**: 사용자가 로그인을 성공하면 서버는 토큰을 발급하여 반환하고, 이후 클라이언트는 매 요청마다 HTTP 헤더에 이 토큰을 포함해 전송하며, 서버는 이를 검증하여 인증 및 인가를 처리합니다.

#### 주제 3: 토큰 관리 및 보안 전략 (Access/Refresh Token & RTR)

* **Access Token**: 인증된 사용자에게 발급되는 **단기 만료 토큰**으로, 클라이언트가 서버의 보호된 리소스에 접근할 때 매번 요청 헤더에 실어 보내는 전용 토큰입니다.
* **Refresh Token**: 액세스 토큰이 만료되었을 때 이를 안전하게 재발급받기 위해 사용하는 **장기 만료 토큰**으로, 오직 재발급 목적 요청에만 사용됩니다.
* **RTR (Refresh Token Rotation)**: 액세스 토큰을 재발급할 때 리프레시 토큰도 함께 무효화하고 **새로운 리프레시 토큰을 매번 다시 생성**하여 클라이언트에게 넘겨주는 보안 강화 기법입니다.
