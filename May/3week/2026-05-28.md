### 새로 배운 내용
#### 주제 1: NoSQL 데이터베이스의 종류와 특징
- **Key-Value Database**: 각 키에 하나의 값이 매핑되는 가장 단순한 형태의 데이터베이스로, 빠른 속도를 자랑합니다. (예: Redis)
- **Document Database**: JSON, XML과 같은 유연한 문서 형식을 사용하여 데이터를 저장하고 관리합니다. (예: MongoDB, CouchDB)
- **Column-oriented Database**: 컬럼(열) 단위로 데이터를 저장하여 대량의 데이터를 빠르게 조회하고 분석하는 데 특화되어 있습니다. (예: Cassandra)
- **Graph Database**: 데이터를 노드와 엣지로 표현하여, 객체 간의 복잡한 '관계'를 중심으로 저장하고 조회합니다. (예: Neo4j)

#### 주제 2: 캐시 (Cache) 전략 비교
- **개념**: 자주 사용하는 데이터나 값을 미리 복사해 두어 빠르게 조회할 수 있도록 돕는 임시 저장소 기술입니다.
- **Local Cache**: 애플리케이션 인스턴스 내부에 독립적으로 존재하여 네트워크 지연 없이 접근 속도가 매우 빠릅니다. 단, 스케일 아웃 시 각 서버 캐시가 독립적으로 동작해 데이터 일관성 유지가 어렵습니다.
- **Global Cache**: 여러 인스턴스에서 하나의 캐시 서버를 공유하므로 데이터의 일관성을 확실하게 보장할 수 있습니다. 다만, 네트워크를 경유해야 하므로 로컬 캐시에 비해 상대적인 지연(Latency)이 발생할 수 있습니다.

#### 주제 3: 데이터베이스 확장(Scaling) 기법
- **샤딩(Sharding)과 파티셔닝(Partitioning)**: 파티셔닝은 하나의 테이블을 논리적인 파트로 나누는 것이며, 샤딩은 파티셔닝과 유사하지만 물리적으로 다른 컴퓨터(서버)로 데이터를 나누어 저장하는 것을 의미합니다.
- **수직 파티셔닝 (Vertical Partitioning)**: 자주 조회되는 컬럼과 그렇지 않은 컬럼을 분리합니다. I/O를 감소시키고 캐싱 효율을 높일 수 있지만, 조인(Join) 필요성이 늘어나 쿼리가 복잡해지고 동시 트랜잭션 관리가 어려워집니다.
- **수평 파티셔닝 (Horizontal Partitioning)**: 데이터를 범위(날짜별), 리스트(지역별), 해시(ID 기준 균등 분배) 등에 따라 행(Row) 단위로 나눕니다. 쓰기 성능이 향상되고 아카이빙/백업이 쉬워지지만, 데이터 불균형이나 파티션 간 쿼리, 인덱스 관리가 까다로워집니다.

#### 주제 4: 데이터베이스 복제 (Replication)
- **Master-Slave 구조**: 똑같은 데이터를 여러 서버에 복제하여 데이터베이스의 가용성을 높이고 부하를 분산시킵니다. 쓰기 작업은 Master에서, 읽기 작업은 주로 Slave에서 처리하는 형태로 활용됩니다.
