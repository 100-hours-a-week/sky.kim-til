### 새로 배운 내용

#### 주제 1: 객체지향 프로그래밍 핵심 개념

* **다형성 (Polymorphism):** 하나의 타입으로 여러 객체를 다루어, 상황에 따라 다른 동작을 수행하게 하는 특성입니다. 자바에서는 주로 부모 클래스나 인터페이스 타입으로 자식 객체를 참조하는 방식으로 구현됩니다.
* **인터페이스 (Interface):** 클래스가 반드시 구현해야 할 메서드의 형태(시그니처: 타입, 이름, 매개변수)만 정의한 설계 구조입니다. 자체 동작 코드는 없습니다. (예: `Car` 인터페이스의 `drive()`)
* **오버로딩 (Overloading):** 메서드 이름은 같지만 매개변수의 형태나 개수를 다르게 정의하여 여러 버전을 만드는 기법입니다. (예: `sum(int a, int b)`와 `sum(int a, int b, int c)`)
* **오버라이딩 (Overriding):** 상속받은(또는 인터페이스의) 메서드를 자식 클래스에서 새로운 동작으로 재정의하는 것입니다. (예: `ElectricCar`와 `GasolineCar`가 각자의 방식으로 `drive()`를 구현)
* **캡슐화 (Encapsulation):** 객체의 내부 상태를 외부에서 직접 접근하지 못하도록 감추고, 메서드를 통해 간접적으로 접근하도록 하는 정보 은닉 개념입니다. 외부의 무분별한 접근으로 인한 데이터 훼손(예: 통장 잔액 강제 변경 등)을 방지합니다.

#### 주제 2: 제네릭 (Generic)

* 데이터 타입을 클래스나 메서드가 선언될 때 지정하지 않고, 사용할 때 구체적인 타입을 지정할 수 있도록 해주는 타입 매개변수 문법입니다.
* 클래스나 메서드 이름 옆에 `<T>`를 선언하여 사용합니다. (예: `Garage<String>`, `Garage<Integer>`) 이를 통해 다양한 타입에 대해 재사용 가능한 코드를 작성할 수 있습니다.

#### 주제 3: 컬렉션 프레임워크와 유틸리티

데이터를 모아서 저장하고 관리하기 위한 구조의 상위 개념으로 List, Set, Map이 있습니다.

* **List:** 순서가 유지되며, 중복을 허용합니다.
* `ArrayList`: 내부적으로 배열을 기반으로 동작.
* `LinkedList`: 노드 기반의 연결 구조 사용.
* `Vector`: ArrayList와 비슷하지만 기본적으로 동기화를 제공하여 멀티스레드 환경에서 안전함.


* **Set:** 순서를 보장하지 않고, 중복을 허용하지 않습니다.
* `HashSet`: 중복과 순서를 모두 보장하지 않음.
* `LinkedHashSet`: 중복은 허용하지 않으나, 삽입 순서는 유지함.
* `TreeSet`: 데이터를 사전 순으로 자동 정렬하여 저장함.


* **Map:** Key-Value 쌍으로 저장하며 Collection 인터페이스를 상속하지 않는 독립된 구조입니다. Key는 반드시 유일해야 합니다.
* `HashMap`: Key의 `hashCode()`를 이용해 해시값을 생성하고 인덱스를 결정합니다. 다른 Key가 같은 해시코드를 가지는 **해시 충돌**이 발생하면, 같은 인덱스에 연결 리스트를 구성하는 **체이닝(Chaining)** 방식으로 해결합니다.
* `LinkedHashMap`: 해시 테이블 기반에 이중 연결 리스트를 결합하여 삽입된 순서를 유지합니다.
* `TreeMap`: 이진 탐색 트리 기반으로 동작하며, Key를 기준으로 오름차순 자동 정렬됩니다.


* **기타 인터페이스:**
* `Iterator`: 컬렉션에 저장된 요소를 순차적으로 하나씩 꺼내기 위한 반복자.
* `Comparator`: 두 객체의 순서를 외부에서 정의하기 위해 사용하는 비교자.



#### 주제 4: 예외 처리 (Exception Handling)

* **throw:** 프로그램 실행 중에 예외 객체를 생성하고, 그 예외를 명시적으로 '발생'시키는 데 사용하는 키워드입니다. (예외 생성)
* **throws:** 메서드가 발생시킬 수 있는 예외를 선언하여, 해당 메서드를 호출한 쪽으로 예외 처리의 책임을 넘기도록 명시하는 키워드입니다. (책임 전가)

### 오늘의 도전 과제와 해결 방법

* 도전 과제 1: `Overloading`과 `Overriding` 용어 및 개념 혼동
* 해결 방법: 코드로 직접 비교 정리함. Overloading은 '매개변수를 다르게 하여 같은 이름의 메서드를 추가(적재)하는 것'이고, Overriding은 '상속 관계에서 기존 메서드의 내부 로직을 덮어쓰기(재정의)하는 것'으로 명확히 구분함.


* 도전 과제 2: `HashMap`의 해시 충돌 해결 방법(체이닝)에 대한 구조적 이해 부족
* 해결 방법: 같은 버킷 인덱스에 데이터가 들어갈 때, 기존 데이터와 새로운 데이터가 연결 리스트(Linked List) 형태로 엮여 저장되는 과정을 시각적으로 그려보며 원리를 이해함.
