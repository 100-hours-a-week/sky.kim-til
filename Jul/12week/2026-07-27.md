### 새로 배운 내용
#### 주제 1: Kubernetes RBAC (역할 기반 접근 제어)
- 사용자와 파드 등의 주체가 쿠버네티스 리소스에 접근할 수 있는 권한을 제어하는 핵심 보안 메커니즘입니다.
- Role(네임스페이스 단위)과 ClusterRole(클러스터 단위)로 권한을 정의하고, Binding을 통해 주체(사용자, 그룹, Service Account)에게 권한을 부여합니다.
- 인증(Authentication)을 통과한 요청에 대해 인가(Authorization)를 수행하며, 보안 사고를 방지하기 위해 권한은 항상 '최소한'으로 부여하는 것이 원칙입니다.

#### 주제 2: Service Account (SA) 및 사용자 관리
- 사람이 아닌 파드(Pod)나 자동화 애플리케이션이 쿠버네티스 API 서버와 통신하기 위해 사용하는 계정입니다.
- 프로메테우스, ArgoCD, 인그레스 컨트롤러 등에는 필요하지만, 일반적인 WAS나 DB 파드에는 API 접근 권한이 굳이 필요하지 않습니다.
- 실무에서는 권한 제어를 위해 네임스페이스의 `default` SA 사용을 피하고, 애플리케이션 단위로 SA를 각각 생성하여 맵핑하는 방식을 권장합니다.
- AWS EKS 환경에서는 IAM(Role, Access Entry)과 연동하여 권한을 관리하며, 온프레미스(kubeadm) 환경에서는 OIDC나 Keycloak 같은 외부 인증 시스템을 연동하여 관리합니다.

#### 주제 3: Helm (쿠버네티스 패키지 매니저)
- 환경(dev, prod 등)마다 달라지는 복잡한 쿠버네티스 YAML 리소스를 템플릿(Template)과 변수 파일(Values.yaml)로 분리해 패키지 형태로 관리하는 도구입니다.
- 패키지 정의인 'Chart'를 클러스터에 설치하면 'Release'라는 하나의 버전 단위로 생성되어, 손쉽게 인프라 버전을 맞추거나 롤백할 수 있습니다.
- `Values.yaml`에 환경별로 변경되는 값만 관리하여 효율적인 배포가 가능하지만, 비밀번호(Secret) 등 민감한 정보가 Git에 평문으로 올라가지 않도록 주의해야 합니다.

#### 주제 4: Ingress (인그레스) 및 라우팅
- 클러스터 외부에서 들어오는 HTTP/HTTPS 요청을 도메인 이름(Host)과 URL 경로(Path)에 따라 적절한 내부 서비스로 프록싱하는 라우팅 규칙입니다.
- 포트 관리가 복잡하고 SSL 처리가 분산되는 NodePort의 단점을 해결하며, 트래픽의 중앙 집중적 제어가 가능합니다.
- Ingress 자체는 단순한 규칙 명세이며, 실제 라우팅 동작은 Nginx 등과 같은 'Ingress Controller'가 담당합니다. (단, HTTP/HTTPS 외에 TCP/UDP 처리가 필요하다면 API Gateway 등을 도입해야 합니다.)
