### 새로 배운 내용
#### 주제 1: Kubernetes Service
- 파드가 삭제되거나 재생성되며 IP가 변경되는 환경에서, 사용자와 시스템 간 안정적으로 접근할 수 있도록 고정된 네트워크 엔드포인트(IP 및 포트)를 제공하는 리소스입니다.
- 쿠버네티스의 DNS를 통해 서비스 이름으로 트래픽을 라우팅하고 로드 밸런싱을 수행하지만, L4(전송 계층)에서 동작하므로 HTTP URL 경로 기반 라우팅은 불가능합니다.
- 용도에 따라 클러스터 내부 통신용인 `ClusterIP`, 노드의 특정 포트를 여는 `NodePort`, 클라우드 외부 로드밸런서를 연결하는 `LoadBalancer` 타입으로 나뉩니다.
- 운영 중 Service의 Selector를 직접 업데이트하면 트래픽 분산과 연쇄 장애(파드 종료 반복 등)가 발생할 수 있으므로, 롤링 업데이트나 블루/그린 배포 방식을 사용하는 것이 안전합니다.

#### 주제 2: Kubernetes Probe
- kubelet이 컨테이너 안의 애플리케이션 상태를 주기적으로 진단하여, 가용성과 안정성을 자동으로 보장하기 위한 헬스체크 메커니즘입니다.
- **Startup Probe**: 애플리케이션 초기화가 완료되었는지 확인하며, 앱 구동이 느릴 때 Liveness Probe가 오작동(무한 재시작)하는 것을 막아줍니다.
- **Liveness Probe**: 앱이 정상 실행 중인지 확인하고 이상이 생기면 컨테이너를 재시작(자동 복구)합니다. 로직을 단순화하여 플래핑(Flapping) 현상을 방지해야 합니다.
- **Readiness Probe**: 사용자 요청을 받을 준비가 되었는지 검사하며, 실패 시 파드를 재시작하지 않고 Service 엔드포인트에서 제외하여 트래픽을 차단합니다.

#### 주제 3: QoS Classes (서비스 품질 등급)
- 워커 노드의 자원(CPU, 메모리)이 부족할 때, 어떤 파드를 우선적으로 보호하고 어떤 파드를 먼저 종료(Evict)할지 결정하는 기준입니다.
- **Guaranteed**: 모든 컨테이너의 Request와 Limit 값이 동일하게 설정된 가장 안정적인 등급으로, 자원 압박 시 가장 마지막에 퇴출당합니다.
- **Burstable**: Request가 Limit보다 작거나 일부만 설정된 상태로, 필요 시 유연하게 자원을 사용하지만 Guaranteed보다 먼저 제거될 수 있습니다.
- **BestEffort**: Request와 Limit이 전혀 설정되지 않아 자원이 보장되지 않으며, 노드 자원이 부족할 때 1순위로 퇴출되는 등급(테스트, 디버깅 용도)입니다.

#### 주제 4: 노드 자원 관리를 위한 Eviction (퇴출)
- 노드의 메모리, 디스크 공간, PID 등이 부족해지는 것을 감지하면, 전체 노드의 마비를 막기 위해 kubelet이 실행 중인 파드를 강제로 종료하여 자원을 확보하는 과정입니다.
- 자원 부족 시 불필요한 이미지와 종료된 컨테이너를 먼저 정리한 후, 상황이 개선되지 않으면 QoS Class 기준에 따라 퇴출 대상을 선정합니다.
- 퇴출(Evicted)된 파드는 API Server에 보고된 후, 자원의 여유가 있는 다른 워커 노드에 다시 스케줄링되어 실행을 이어갑니다.
