### 새로 배운 내용
#### 주제 1: Continuous Integration (CI)
- **CI의 정의와 필요성**: 개발자가 작성한 코드를 자동으로 통합 및 테스트하여 품질을 유지하는 프로세스입니다. 코드 충돌이나 에러를 조기에 발견하고 자동화하기 위해 필수적입니다.
- **CI 구성의 4가지 원칙**: 단일 코드 기준 베이스(main/dev 분리), 변경 사항의 잦은 통합, 재현 가능한 빌드(환경 종속성 제거), 그리고 모든 과정의 자동화된 테스트를 포함합니다.
- **실무 파이프라인 운영**: PR 단계에서는 컴파일과 단위 테스트 같은 빠른 검사를, main 단계에서는 통합/E2E 테스트 및 Docker 이미지 빌드 등 최종 검증을 수행합니다.

#### 주제 2: Test Code (테스트 코드) 및 TDD
- **테스트 코드의 목적**: 소스 코드의 단순 빌드를 넘어 기대하는 동작이 실제로 이루어지는지 코드로 검증합니다. 핵심 비즈니스 로직과 복잡한 예외 처리 로직의 우선순위가 높습니다.
- **작성 규칙과 구조**: 실행 순서나 외부 요인에 영향을 받지 않도록 독립적으로 작성하며, 가독성을 높이기 위해 `Given-When-Then` 패턴을 활용합니다.
- **TDD 주의점**: 테스트를 먼저 작성해 작은 단위로 개발하는 장점이 있으나, 실패 상황을 제대로 예측하지 못하면 의미 없는 통과용 코드가 될 수 있으므로 주의해야 합니다.

#### 주제 3: Continuous Deployment (CD) 및 무중단 배포
- **CD의 정의와 이점**: 자동화된 테스트를 통과한 코드를 운영 환경에 자동으로 배포하는 프로세스입니다. 수동 배포 시 발생하는 인적 오류(Human Error)와 소요 시간을 크게 줄여줍니다.
- **무중단 배포 (Zero-Downtime)**: 서비스 다운타임 없이 앱을 업데이트하는 방식으로, 처리 중인 기존 요청을 안전하게 마무리하는 우아한 종료(Graceful Shutdown)가 핵심입니다.
- **주요 배포 전략**: 트래픽을 한 번에 전환하지만 인프라 비용이 2배인 **Blue/Green**, 점진적으로 서버를 교체하는 **Rolling**, 소수 트래픽에만 먼저 노출해 검증하는 **Canary** 배포가 있습니다.

#### 주제 4: 인프라 환경 구축 (Amazon ECR & AWS CodeDeploy)
- **Amazon ECR**: Docker 이미지를 안전하게 저장하고 AWS 환경에서 빠르게 연동할 수 있는 컨테이너 저장소입니다. 명확한 태그 사용 및 스토리지 비용 관리를 위한 수명 주기(Life Cycle) 설정이 중요합니다.
- **AWS CodeDeploy**: Auto Scaling 등으로 인스턴스가 동적으로 변하는 환경에서도 타겟 그룹 기반으로 배포를 자동화해 줍니다. `AppSpec` 파일로 배포 스크립트를 정의합니다.
- **실무 CI/CD 연동**: 주로 `GitHub Actions`를 통해 빌드와 ECR 푸시를 진행하고, `CodeDeploy`를 사용해 설정된 전략(Blue/Green 등)에 맞춰 EC2에 배포하는 조합을 많이 사용합니다.
