### 새로 배운 내용
#### 주제 1: Continuous Integration (CI)
- 개발자가 작성한 코드를 자주 통합하고, 자동화된 빌드 및 테스트를 수행하여 코드 품질을 지속적으로 유지하는 프로세스입니다.
- 단일 코드 베이스 유지, 잦은 변경 사항 통합, 재현 가능한 빌드 환경(POM, Dockerfile 등), 자동화된 테스트가 CI를 구성하는 4대 핵심 원칙입니다.
- CI 품질 게이트를 설정하여 코드가 다음 단계로 넘어가기 전 자동화된 품질 기준을 거치도록 하며, 빠른 검사와 느린 검사를 분리해 파이프라인의 속도와 신뢰성을 동시에 확보해야 합니다.

#### 주제 2: 테스트 코드(Test Code)와 TDD
- 테스트 코드는 기능 검증, 회귀 버그 방지, 요구사항 문서화, 리팩토링 시 변경 안정성 확보 등의 중요한 역할을 수행합니다.
- 좋은 테스트는 하나의 중요한 동작만을 검증하며, 실행 순서나 외부 환경에 영향받지 않고 항상 독립적이고 동일한 결과를 내야 합니다. (Given-When-Then 패턴 활용)
- TDD는 테스트를 먼저 작성해 요구사항을 설계하는 방법론이나, 맹목적인 커버리지 달성보다는 핵심 비즈니스 로직과 복잡한 계산 로직을 우선적으로 검증하는 것이 실용적입니다.

#### 주제 3: Continuous Deployment (CD)
- 자동화된 테스트를 통과한 코드를 실제 운영 환경까지 자동으로 배포하는 프로세스로, 수동 배포 시 발생하는 병목과 작업자 간의 결과물 변수를 제거합니다.
- CI 과정에서 생성된 배포 가능한 결과물(Artifact)을 별도 보관하여 작업 간 데이터 공유, 디버깅, 배포 실패 시 즉각적인 롤백에 활용합니다.
- 컨테이너가 실행되더라도 내부 애플리케이션의 정상 동작을 보장하지 않으므로, 반드시 Health Check와 문제 발생 시 이전 버전으로 복구하는 Rollback 전략이 수반되어야 합니다.

#### 주제 4: GitHub Actions
- GitHub 저장소 내에서 push, pull_request 등의 특정 이벤트가 발생했을 때 빌드, 테스트, 배포를 자동화하는 CI/CD 도구입니다.
- 자동화의 전체 절차를 정의하는 Workflows(.yml 구조), 작업이 실행되는 환경인 Runner, 독립적인 실행 단위인 Job과 순차적 단계인 Step 등 유기적인 구성 요소로 이루어집니다.
- Job은 각기 다른 Runner를 사용하여 프로비저닝에 추가 시간이 소요되므로, 성능 최적화를 위해 Job을 너무 잘게 쪼개지 않는 것이 중요합니다.
