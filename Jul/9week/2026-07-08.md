### 새로 배운 내용
#### 주제 1: AWS ECR (Elastic Container Registry) 이해 및 활용
- **개념 및 특징:** AWS 환경에 최적화된 안전한 컨테이너 이미지(Docker 등) 저장소입니다. IAM을 통한 세밀한 접근 권한 제어가 가능하며, 이미지 업로드 시 취약점을 자동으로 검사해 주는 보안 스캔(Basic Scanning, AWS Inspector) 기능을 기본 제공합니다.
- **사용 이점:** ECS, EKS, EC2 등 AWS 내부 컴퓨팅 리소스와 연동이 쉽고 내부 네트워크를 사용하므로 외부 통신 비용이 절감됩니다. CI/CD 파이프라인에서 빌드된 이미지를 보관하고 각 서버가 안전하게 Pull 받을 수 있는 핵심 중추 역할을 합니다.
- **이미지 주소 및 구성 요소:** `계정ID.dkr.ecr.리전.amazonaws.com/레포지토리명:태그` 형식의 주소를 사용합니다. 애플리케이션 실행 패키지인 'Image', 이미지를 저장하는 'Registry', 특정 이미지의 버전을 모아두는 공간인 'Repository', 그리고 버전을 구분하는 'Tag'로 구성됩니다.
- **실무 사용 시 주의사항:** 여러 개발자가 협업할 때 버전 충돌 방지를 위해 `latest` 태그 사용을 지양하고 명확한 명명 규칙을 써야 합니다. 또한 이미지 보관 용량만큼 비용이 발생하므로 **Life Cycle(수명 주기) 정책**을 설정해 오래된 이미지를 자동 삭제해야 하며, Private Subnet 연동 시 NAT 게이트웨이 비용 절감을 위해 **VPC EndPoint**를 활용하는 것이 좋습니다.

#### 주제 2: AWS CodeDeploy를 활용한 배포 자동화
- **개념 및 필요성:** EC2, ECS 등의 환경에 애플리케이션 배포를 자동화하는 서비스입니다. 수많은 서버에 수동 배포하는 노가다를 줄여주며, 특히 Auto Scaling Group(ASG)처럼 서버 인스턴스가 동적으로 생성되고 삭제되는 환경에서 타겟 대상에게 안정적으로 배포하기 위해 필수적입니다.
- **핵심 구성 요소:** 배포 단위인 **Application**, 태그를 기반으로 배포 대상을 묶는 **Deployment Group**, 배포할 결과물인 **Revision**, 복사 경로와 실행할 스크립트 등 배포 절차를 정의하는 YAML 설명서인 **AppSpec**, 그리고 배포 전략을 정의하는 **Deployment Configuration**이 있습니다.
- **GitHub Actions와의 조합:** 실무에서는 범용 자동화 도구인 GitHub Actions로 CI(빌드, 테스트, ECR 푸시)를 담당하고, AWS 리소스 관리에 특화된 CodeDeploy로 CD(안정적 배포 전략 수행, 롤백 등)를 담당하도록 역할을 분리하여 함께 사용합니다.
- **장단점 비교:** 다양한 배포 전략(Blue/Green, Rolling 등)을 쉽게 적용하고 빠른 릴리즈가 가능하다는 장점이 있습니다. 하지만 IAM, Role 설정, AppSpec 작성 등 초기 세팅이 복잡하며, 대상 EC2에 CodeDeploy Agent를 설치하고 관리해야 하는 운영 포인트가 늘어난다는 단점도 존재합니다.

### 오늘의 도전 과제와 해결 방법
- 도전 과제 1: 100만 MAU 트래픽을 대비한 컨테이너 이미지 저장소 아키텍처 한계 직면
    - 현재 EC2에 자체 레지스트리를 구축하여 배포하는 방식을 사용 중이나, 트래픽 증가에 따라 서버 대수가 늘어날 경우 EC2의 디스크 용량 한계와 불필요한 비용 증가라는 비효율이 발생할 것을 인지함.
    - 해결 방법: 클라우드 기반의 완전 관리형 서비스인 AWS ECR 도입을 고려함. 이를 통해 이미지를 더욱 안전하고 무제한으로 저장하며, 다수의 EC2에서 빠르고 쉽게 접근하여 배포할 수 있는 확장성 높은 아키텍처로 개선 방향을 설정함.

### 오늘의 회고
- 현재 구축한 자체 레지스트리 기반의 EC2 배포 구조가 대용량 트래픽 상황에서는 적합하지 않을 수 있다는 점을 스스로 묻고 깨닫게 되었습니다. 100만 MAU 서비스처럼 다수의 서버를 운영해야 하는 상황에서는 비용과 효율성을 고려해 AWS ECR과 같은 클라우드 네이티브 솔루션을 도입하는 것이 훨씬 나은 선택임을 이해했습니다.
- 예전 카카오 현직자 특강에서 들었던 "인프라에는 정답이 없다. 최적의 방안을 고를 수 있는 폭넓은 지식이 필요하다"는 말씀이 오늘 배움을 통해 완벽하게 공감되었습니다. 앞으로도 단순한 구현을 넘어, 확장성과 운영 효율성을 챙길 수 있는 다양한 인프라 옵션들을 꾸준히 학습해야겠습니다.
