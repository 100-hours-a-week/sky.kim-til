### 새로 배운 내용
#### 주제 1: Docker Bridge Network의 개념과 필요성
- **Bridge Network의 역할**: 동일한 호스트 내에 있는 컨테이너들이 서로 통신할 수 있도록 돕는 도커의 기본 가상 네트워크입니다. 리눅스와 도커 소프트웨어를 통해 가상의 스위치(Docker Bridge)와 연결 케이블(veth pair)을 만들어냅니다.
- **필요성**: 모든 컨테이너를 호스트 네트워크에 바로 연결하면 포트 관리의 어려움, 보안 취약점(예: MySQL 등 주요 DB의 외부 노출), 그리고 컨테이너 재생성 시 IP 변경에 따른 연결 단절 등의 문제가 발생합니다.
- **독립성 확보**: 도커는 컨테이너마다 독립적인 네트워크 환경(자신만의 가상 네트워크 인터페이스인 eth0)을 부여하여, 필요한 컨테이너끼리만 안전하게 통신하도록 격리합니다.

#### 주제 2: 기본 Bridge와 사용자 정의 Bridge의 차이
- **기본 Bridge**: 도커 설치 시 자동으로 생성되는 네트워크입니다. 컨테이너 IP를 통한 통신은 가능하지만, IP는 컨테이너가 재생성될 때마다 바뀌기 때문에 연결 안정성이 떨어집니다.
- **사용자 정의 Bridge**: `docker network create` 명령어로 생성하며, **자동 DNS 기능을 지원**하는 것이 핵심입니다. IP 대신 '컨테이너 이름'으로 통신할 수 있어 IP 변동에 구애받지 않고 안정적인 연결이 가능합니다.
- **실무 베스트 프랙티스**: 격리 수준이 높고 실행 중 네트워크 연결/해제가 자유로운 사용자 정의 브릿지 사용을 권장합니다. 애플리케이션 설정 파일에 절대 IP를 하드코딩하지 않고 컨테이너 이름(DNS)을 사용하는 것이 좋습니다.

#### 주제 3: 실무적인 컨테이너 아키텍처 패턴
- **Network Segmentation (네트워크 분할)**: Nginx, API, DB를 분리하고 용도에 맞게 네트워크를 할당합니다. 예를 들어 API 컨테이너에만 2개의 네트워크를 연결하여 외부(Nginx)와 내부(DB) 통신의 브릿지 역할을 하게 만들어 보안을 강화합니다.
- **사이드 카 패턴 (Sidecar Pattern)**: 메인 애플리케이션 컨테이너 옆에 로깅, 모니터링, 프록시 역할을 하는 보조 컨테이너를 배치하여 단일 책임 원칙(SRP)과 관심사의 분리를 실현합니다.
- **워커 패턴 (Worker Pattern)**: 사용자의 요청을 동기적으로 바로 처리하지 않고, 메시지 브로커 등을 별도 네트워크에 분리하여 비동기로 작업을 처리하는 아키텍처 방식입니다.

#### 주제 4: 그 외의 Docker 네트워크 드라이버
- **Host Network**: 컨테이너가 호스트 서버의 네트워크 인터페이스를 격리 없이 직접 공유하여 사용하는 방식입니다.
- **Overlay Network**: 여러 대의 물리적 호스트 서버에 분산된 컨테이너들을 마치 하나의 가상 서브넷에 있는 것처럼 통신할 수 있게 해주는 가상의 L2 네트워크입니다.
- **macvlan Network**: 컨테이너에 별도의 MAC 주소와 IP를 할당하여, 가상 환경이 아닌 실제 물리 네트워크상의 한 장치처럼 동작하도록 구성하는 방식입니다.
