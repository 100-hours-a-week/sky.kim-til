### 새로 배운 내용
#### 주제 1: Portainer와 컨테이너 환경 관리
- **Portainer의 개념과 역할:** Docker 및 Kubernetes 환경을 직관적인 웹 GUI로 관리할 수 있는 도구입니다. 로컬 환경에 최적화된 Docker Desktop과 달리, 다중 서버 관리와 역할 기반 접근 제어(RBAC)를 지원하여 실무 인프라 운영 및 DevOps 팀의 업무 효율성을 크게 높여줍니다.
- **아키텍처 및 동작 방식:** UI와 관리를 담당하는 Portainer Server, 실제 컨테이너를 실행하는 Docker Engine, 원격 환경 정보를 제공하는 Agent(일반/Edge)로 구성됩니다. 도커 제어를 위해 Docker Socket을 활용하여 통신합니다.
- **실무 활용과 보안 주의사항:** 장애 발생 시 GUI를 통해 직관적인 가시성을 제공하여 빠른 원인 파악을 돕고, 소규모 운영 환경에서 무거운 모니터링 툴을 대체할 수 있습니다. 단, Docker Socket의 권한이 매우 막강하므로 Portainer 컨테이너는 절대 외부 인터넷에 직접 노출해서는 안 되며, Private Subnet이나 VPN을 통해서만 접근해야 합니다.

#### 주제 2: Docker Volume을 활용한 데이터 영속성 보장
- **Volume의 필요성:** 도커 컨테이너는 기본적으로 임시 레이어에 쓰기 작업을 수행하므로, 컨테이너 삭제 시 데이터가 함께 휘발되는 비영속적인 특징을 가집니다. 이를 해결하고 데이터를 영구적으로 보존하기 위해 컨테이너 외부(Host OS)의 저장 공간을 활용하는 Volume이 필요합니다.
- **동작 원리 및 장점:** 데이터를 호스트 OS에 저장함으로써 컨테이너를 삭제하고 재배포해도 데이터가 유지됩니다. 또한, 외부 저장소를 마운트하는 방식이므로 여러 컨테이너 간에 동일한 데이터를 안전하게 공유할 수 있습니다.
- **실무 적용 사례:** 영속성이 보장되어야 하는 데이터베이스(DB) 컨테이너, 다중 WAS 환경에서 공유해야 하는 파일 업로드 임시 폴더, 공통적으로 적용해야 하는 설정 파일(Nginx, Spring env) 관리, 그리고 안전한 로그 보관 등에 핵심적으로 사용됩니다.
