### 새로 배운 내용
#### 주제 1: AWS Lambda와 서버리스 컴퓨팅
- OS 관리나 용량 조절 등 서버 운영을 AWS에 위임하는 이벤트 기반 서비스로, 코드가 실행되는 시간에만 과금되어 비용 효율적이고 확장에 유연함.
- S3 파일 처리나 크론잡 등에 적합하지만, 콜드 스타트 지연, 상태 비저장(Stateless), 최대 15분 실행 제한이라는 한계가 있음.
- 실무에서는 함수 하나에 여러 로직이 섞이지 않도록 단일 책임 원칙을 지키고, RDS 커넥션 보호를 위해 중간에 큐(SQS)를 두거나 프로비저닝을 통해 콜드 스타트에 대응해야 함.

#### 주제 2: API Gateway의 역할 및 활용
- 분산된 마이크로서비스 환경 등에서 클라이언트에게 단일 진입점을 제공하고 백엔드로 요청을 라우팅하는 완전관리형 서비스임.
- 개별 서버가 비즈니스 로직에만 집중할 수 있도록 JWT 인증/인가 검증, CORS 처리, 트래픽 제한(Throttling) 등의 공통 보안 및 관리 로직을 전담함.
- 단순히 웹 트래픽을 분산하고 헬스체크만 하는 목적이라면 ALB가 낫지만, API 관리와 보안 통제가 핵심이라면 API Gateway를 사용하는 것이 적절함.

#### 주제 3: CloudWatch 및 시스템 옵저빌리티(Observability)
- 옵저빌리티란 지표(Metrics), 로그(Logs), 분산 추적(Traces) 데이터를 통해 시스템을 열어보지 않고도 내부 상태와 병목 원인을 정확히 추론할 수 있는 능력을 말함.
- 문제 발생 시 추측이 아닌 데이터 기반으로 원인을 파악하기 위해, 실무에서는 로그를 JSON 형태로 구조화하여 검색과 분석을 용이하게 만듦.
- 운영자의 '알람 피로'를 방지하기 위해 모든 API가 아닌 핵심 API의 주요 지표(예: 5xx 에러 급증, p95 응답 시간)에 집중하여 즉각적인 대응이 필요한 경우에만 알람을 설정하는 것이 중요함.
