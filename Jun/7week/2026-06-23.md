### 새로 배운 내용
#### 주제 1: AWS 파일 공유 스토리지 및 마운트 (EFS & NFS)
- **EFS (Elastic File System)**: AWS에서 제공하는 완전관리형 네트워크 파일 시스템으로, 사용자가 스토리지를 직접 설정하거나 용량을 관리할 필요 없이 자동으로 확장 및 축소됩니다. 여러 EC2 인스턴스에서 동시에 접근해야 하는 파일 스토리지 구성에 사용합니다.
- **NFS (Network File System)**: 네트워크상에서 다수의 클라이언트가 동일한 파일 시스템에 안전하게 접근하고 파일을 공유할 수 있도록 해주는 표준 프로토콜입니다.
- **Mount (마운트)**: 외부 저장소(EFS 등)나 파일 시스템을 운영체제의 디렉토리 트리에 연결하여, 해당 파일 시스템을 로컬 저장소처럼 사용할 수 있게 만드는 필수 과정입니다.

#### 주제 2: AWS 객체 스토리지 (S3 & Presigned URL)
- **S3 (Simple Storage Service)**: 대규모 데이터를 안전하고 경제적으로 저장 및 검색할 수 있는 뛰어난 확장성과 내구성, 고가용성을 지닌 AWS의 완전관리형 객체 스토리지 서비스입니다.
- **Presigned URL (사전 서명된 URL)**: S3와 같은 클라우드 스토리지에서 권한이 없는 일반 사용자도 정해진 시간 동안만 특정 객체에 접근(읽기/쓰기 등)할 수 있도록 허용하는 임시 URL입니다. 이를 통해 서버에서 직접 파일을 서빙하는 부담을 줄여 서버 부하를 크게 감소시킬 수 있습니다.

#### 주제 3: AWS 관계형 데이터베이스 및 고가용성 구성 (RDS)
- **RDS (Relational Database Service)**: 클라우드 환경에서 관계형 데이터베이스를 손쉽게 생성, 운영, 확장할 수 있게 해주는 완전관리형 서비스입니다. EC2 인스턴스에 DB를 직접 구축하고 관리할 때 발생하는 운영 부담을 크게 줄여줍니다.
- **Read Replica (읽기 전용 복제본)**: 기본(Master) 데이터베이스의 데이터를 그대로 복사하여 읽기(Read) 트래픽만 전담하는 데이터베이스 서버입니다. 데이터베이스의 읽기 부하를 분산시키고 지연 시간을 개선하는 데 활용됩니다.
- **Multi AZ (다중 가용 영역)**: RDS를 두 개 이상의 서로 다른 물리적 가용 영역에 자동 복제하여 배치하는 고가용성 아키텍처입니다. 하나의 데이터베이스나 가용 영역에 장애가 발생하더라도 다른 쪽에서 서비스를 지속할 수 있도록 보장합니다.

- 이론적인 개념들을 엮어 실제 인프라 구조를 설계하는 일은 생각보다 훨씬 까다롭다는 것을 느꼈습니다. 세상에 완벽한 기술은 없으며, 하나의 기술을 선택하면 트레이드오프(Trade-off)가 수반됨을 깊이 깨달았습니다.
- 손실을 감수할 만큼의 확실한 도입 근거가 있는지, 현재 상황에서 최선의 선택인지 끊임없이 검증하는 과정이 인프라 설계의 핵심임을 배웠습니다.
- 서비스의 안정적인 운영과 관리는 머릿속 지식만으로는 한계가 있으며 직접 부딪혀보는 경험이 절대적으로 필요함을 실감했습니다.
- 앞으로 진행될 카테부 기간 동안 직접 서비스를 설계하고 구축해 보며, 단순한 구현을 넘어 기술적 의사결정에 대한 깊이 있는 고민과 치열한 실무 경험을 쌓아갈 계획입니다.
