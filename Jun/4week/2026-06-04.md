### 새로 배운 내용
#### 주제 1: Spring Web MVC 흐름 제어 (Filter vs Interceptor)
- **필터 (Filter)**: 서블릿 컨텍스트 내에서 디스패처 서블릿으로 요청이 전달되기 전후에 거치는 관문으로, URL 패턴에 맞는 요청에 대한 부가 처리를 담당합니다.
- **인터셉터 (Interceptor)**: 디스패처 서블릿과 컨트롤러 사이의 요청 및 응답에 대한 부가 처리를 담당하며, 컨트롤러 호출 전후에 동작하여 기능을 수행합니다.

#### 주제 2: Spring 예외 처리 (Exception Handling)
- **@ExceptionHandler & @RestControllerAdvice**: 컨트롤러 계층에서 발생하는 에러를 개별적으로 처리하거나, 전역적으로 예외를 잡아 처리하는 클래스를 선언하여 예외 클래스와의 강한 결합을 줄일 수 있습니다.
- **@ResponseStatus 및 응답 커스텀**: 에러 발생 시 HTTP 상태 코드를 변경할 수 있습니다. 스프링의 기본 에러 응답 형태를 클라이언트의 요구사항에 맞게 유연하게 수정하고 커스텀하는 데 사용됩니다.

#### 주제 3: 파일 처리 및 스토리지 설계
- **파일 업로드 및 처리 전략**: 로컬 환경을 기준으로 설계하되 향후 클라우드 확장을 고려해야 합니다. 지원할 확장자(jpg, webp, png 등), 크기 제한, 압축 및 포맷 변환 여부를 사전에 명확히 정의해야 합니다.
- **데이터 저장소 및 고아 이미지 관리**: 파일을 로컬 스토리지, RDB, 또는 외부 스토리지 중 어디에 저장할지 결정해야 합니다. 특히, 유저 데이터가 삭제되어 DB나 UI에서는 참조하지 않으나 스토리지 공간만 차지하는 '고아 이미지'를 처리하는 전략이 필요합니다.

#### 주제 4: 백엔드 시스템 설계 프로세스
- **건축과 같은 백엔드 설계**: 개발은 아파트 단지를 짓는 것과 같아, 하나의 도메인을 잘 설계해 두면 내부 구성 요소의 유사성 덕분에 다른 도메인으로 확장하기 용이합니다. 따라서 기초 공사(설계)를 튼튼히 하는 것이 핵심입니다.
- **체계적인 12단계 설계 파이프라인**: 기획안 검토(0)를 시작으로 협업 방식 정의(1), 도메인 요구사항 분석(2), REST API 및 DB 스키마 설계(3~4), 코드 아키텍처 및 엔티티/DTO/인터페이스 정의(5~9)를 거쳐 최종 검토(10) 후 실제 개발(11)에 착수해야 합니다.
