### 새로 배운 내용
#### 주제 1: 동시성(Concurrency)과 병렬성(Parallelism)의 이해
- **동시성(Concurrency):** 하나의 CPU 코어에서 작업 시간을 잘게 쪼개어 빠르게 전환(Context Switching)함으로써, 물리적으로는 아니지만 마치 여러 작업이 동시에 실행되는 것처럼 보이게 하는 논리적 개념입니다.
- **병렬성(Parallelism):** 멀티 코어 환경에서 물리적으로 여러 작업을 동시에 처리하는 기술입니다. 대규모 데이터 처리나 실시간 처리에 유리하지만, 하드웨어(코어 수)의 물리적 제한을 받습니다.
- **실무 적용 포인트:** 병렬성이 항상 정답은 아닙니다. 작업 분할 및 결과 병합 비용, 스레드 생성 비용이 싱글 코어 동시성 처리 비용보다 클 수 있기 때문입니다. 또한, 멀티스레드 환경에서는 공유 자원 접근 시 발생하는 경쟁 상태(Race Condition)를 철저히 관리해야 합니다.

#### 주제 2: 운영체제 스케줄러(Scheduler)의 역할과 분류
- 스케줄러는 시스템 자원(CPU, 메모리 등)을 적절히 분배하기 위해 프로세스나 스레드의 실행 순서를 관리하고, 작업 간의 컨텍스트 스위칭을 담당하는 운영체제의 핵심 요소입니다.
- **장기 스케줄러:** 디스크에서 메모리로 로드할 작업을 선택하여 시스템의 다중 프로그래밍 정도를 조절합니다.
- **중기 스케줄러:** 메모리 부족 시 활성화된 프로세스 일부를 디스크의 스왑 영역으로 쫓아내어(Swapping) 자원을 확보합니다.
- **단기 스케줄러:** 메모리의 준비 상태인 프로세스 중 다음에 CPU를 점유할 작업을 밀리초 단위로 매우 빠르게 결정합니다.

#### 주제 3: 스케줄링 알고리즘과 트러블슈팅
- **주요 알고리즘:** 들어온 순서대로 처리하는 `FCFS`, 가장 짧은 작업을 먼저 처리해 평균 대기시간을 줄이는 `SJF` 및 `SRTF`, 타임 슬라이스를 균등하게 부여해 공정성을 확보하는 `Round Robin` 등이 있습니다.
- **선점형(Preemptive) 방식:** 현대 운영체제(Linux, Windows, Mac)는 여러 작업을 동시에 안정적으로 실행하기 위해 OS가 CPU 자원을 강제로 회수할 수 있는 선점형 방식을 채택하고 있습니다.
- **개발자 관점에서의 중요성:** 백엔드 개발자가 직접 스케줄러를 구현하지는 않지만, 성능 최적화 및 트러블슈팅 시 필수적인 지식입니다. 예를 들어, CPU 사용량은 낮은데 처리 속도가 안 나온다면 과도한 스레드 생성으로 인한 컨텍스트 스위칭 오버헤드를 의심해 볼 수 있습니다.
